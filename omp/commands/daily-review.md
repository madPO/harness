Command arguments: `$ARGUMENTS` (may be empty).

You are running **/daily-review** for my engineering reflection workflow.

1. Read `skill://engineering-reflection` and `skill://engineering-reflection/templates/Daily.md`. Follow the skill's private vault access and approval rules, independent of the working directory. Use the argument or local date; ask if ambiguous. Check for an existing dated journal and merge without overwriting it.
2. Ask: **"How did your working day go? What did you work on, and what stood out?"** Let me speak freely.
3. Extract volunteered tasks, progress, results, frustrations, blockers, decisions, learning, collaboration, feedback, and next steps. Do not force sections or turn feelings into diagnoses or criticism.
4. Resolve task mentions against existing task notes. Read relevant expectations when useful. Ask about ambiguous matches. If none exists, leave plain text and offer `/task-start` later.
5. Ask at most 1–3 useful clarifying questions, preferably one at a time. Prioritize unexpected outcomes, concrete helpful contributions, or uncertainty about tomorrow. Ask about thanks only when useful. Accept "nothing else".
6. Draft a readable journal using the template and resolved wikilinks at first mention. Preserve my voice.
7. Separately propose other file updates. Routine mentions, progress, frustration, and tentative theories mean journal links only. Significant verified discoveries, decisions, or explicit status or scope changes merit a brief append-only dated task entry linked to the day. Explicit completion may warrant status and outcome updates, never changes to frozen expectations. Do not change tasks solely because they were mentioned.
8. Show the journal preview, exact vault-relative path, and cross-file change list. Request approval. Save or merge the journal, then apply only explicitly approved task changes. Check actual file results before reporting success.
9. Return the journal wikilink and a short saved-content recap. Do not automatically start a weekly review, send recognition, or create an experiment.

The daily entry owns the day's experience; task notes are curated summaries, not duplicate diaries.
